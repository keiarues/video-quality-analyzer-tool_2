# グラフ表示中のプレビュー再生負荷検証

## 専用テスト画面

通常画面とは別に、動画プレビューとSSIMのフレームグラフを表示する専用画面を作る。
同一の再生動画・区間・画面サイズで、グラフなし、1本、2本、全本を比較する。
再生位置線と評価値ラベルの更新を切り替え、折れ線描画と動的更新の負荷を切り分ける。

## SSIM結果の保存と再利用

- 準備操作で基準動画と各比較動画のSSIMを計算し、正常終了した結果だけをファイルに保存する。
- 保存対象はフレーム番号ごとのSSIM値、平均値、動画情報、基準動画と比較動画の識別情報、保存形式のバージョンとする。
- 再生テストの開始時は保存済み結果を読み込む。評価計算を実行せず、評価処理の負荷が再生測定に混ざらないようにする。
- 保存結果がない場合は準備が必要と表示し、再生テスト開始を契機に自動計算しない。
- 動画のパス・サイズ・最終更新日時と評価条件を照合し、一致しない結果は利用しない。再計算は明示的な準備操作で行う。
- 破損ファイルや未対応バージョンは理由を表示し、再生テストに使用しない。
- 保存先を画面で確認できるようにし、アプリを終了しても再利用できるようにする。
- 評価結果ファイルには動画識別用の情報を保存するが、性能ログには動画のフルパスを記録しない。

## 検証と記録

保存後にアプリを再起動し、評価処理を呼ばずに同じフレーム値を読み込めることを確認する。
動画変更、欠落、破損時に古い結果を利用しないことも確認する。
CPU・メモリ、動画フレーム反映間隔、グラフ更新所要時間を記録する。
アプリ内のフレーム反映と画面への実提示fpsは区別する。

## 実装状況

専用画面 `GraphPlaybackTestWindow` とSSIMのJSON保存を実装した。
通常画面の評価結果の保持方式は変更していない。

## 起動方法

Releaseビルド後、初回だけ `tools/Run-GraphPlaybackTest.ps1 -Prepare` を実行する。
配置済みの基準動画とAV1・H.265比較動画4本を評価し、
`measurement-results/graph-playback/ssim.json` に保存する。

`tools/Run-GraphPlaybackTest.ps1` で保存結果を読み込んだ専用画面を起動する。
同じ画面はリポジトリ直下の `グラフ再生検証を起動.cmd` からも開ける。
再生・一時停止・グラフの本数変更・グラフからのシークができる。
`-Auto` を付けると、0・1・2・4本×再生位置更新なし／ありの8条件を各35秒実行して終了する。
結果は保存先と同じフォルダーの `playback-日時.json` に記録する。
起動時の読み込み失敗は `ssim.json.error.txt` に記録する。

## 測定の範囲

- プレビューは基準動画1本、グラフは実際に評価した比較動画を用いる。データの複製による水増しはしない。
- 通常画面と同じ `Av1PreviewPlayer` と `QualityGraphPanel` を使う。専用画面ではファイルグラフを隠す。
- 本数0でも軸は残す。静的なグラフを維持したまま、再生位置と評価値の更新の有無を比較する。
- PTS 2秒以上32秒未満の異なる元フレーム番号を画像反映通知から数える。
- 反映間隔の95パーセンタイル・最大値、35秒全体のCPU・メモリ・グラフ更新呼び出し時間を記録する。
- グラフ更新呼び出し時間には、その後WPFが行うレイアウト・描画時間は含まない。
- 実画面提示fps、物理パネルの表示、GPU負荷、通常画面の左右同時再生はこの試験では未測定。
- 各条件1回の切り分け試験であり、性能合格を再判定するものではない。

## 成功した確認

- 配置済みdotnetで `build src/VideoQualityAnalyzer.App -c Release --no-restore -m:1 /nodeReuse:false`：警告0、エラー0。
- `tests/Run-Tests.ps1 -NoRestore`：26件実行、26件合格。保存・再読み込み・動画変更・破損結果の試験を追加。
- `tools/Run-GraphPlaybackTest.ps1 -Prepare`：実動画4本のSSIMを保存。
- `tools/Run-GraphPlaybackTest.ps1 -Auto`：別プロセスで保存結果を読み込んで8条件を完了。
- 画面確認：プレビュー、SSIM折れ線、再生位置、複数線の配置をスクリーンショットで確認。滑らかさの目視判定とは区別する。

制限付き実行でMSTestのデータ収集プロセス接続がタイムアウトしたため、通常環境で再実行し合格した。
実行中DLLのロックによるビルド失敗は、テスト画面終了後のビルドで解消した。

次の作業候補は、専用画面で静的な折れ線と動的な再生位置表示を別レイヤーにし、
更新頻度の制限や表示幅に応じた点数削減と比較すること。通常画面の負荷対策はまだ行っていない。

## レイヤー分離の検証

専用画面の「再生位置を別レイヤー」を有効にすると、折れ線・軸のCanvasの上に
再生位置線・左右の評価値・時刻のCanvasを重ねる。初期値は有効。
無効にすると従来どおり同じCanvasに戻せる。
通常画面は従来経路を維持し、専用画面だけで効果を検証する。

比較条件を揃えるため、今回の分離では点数削減、ビットマップキャッシュ、更新頻度の制限を加えていない。
自動測定結果には `SeparatePlaybackLayer` を追加し、どちらの構造を測ったか識別する。
