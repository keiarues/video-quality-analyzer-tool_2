# リファクタリングの進捗と次の対象

更新日: 2026-11-17

アプリの現在のフォルダー構成は[アプリのソース配置](../src/VideoQualityAnalyzer.App/README.md)を参照。主画面、グラフ、利用者向け画面、入力部品、再生部品を機能別フォルダーに移した。C#名前空間と起動引数は変更していない。

## 今回整理した範囲

- `MainWindow.xaml.cs` は状態と初期化、起動時の検証振り分け、終了処理を担当する。約1,077行から149行になった。
- `MainWindow.Library.cs` は元動画の変更・削除とグループ操作を担当する。動画登録とファイルドロップは `MainWindow.LibraryFiles.cs`、一覧表示・選択維持・並べ替えは `MainWindow.LibraryView.cs` に分けた。
- `MainWindow.PreviewSelection.cs` は一覧・左右プレビューの選択変更と、再生状態を保った表示更新を担当する。プレビュー指定の動画ID検証は `SelectionService.ApplyOverrides` に集約した。
- `MainWindow.Playback.cs` は左右スロットの開閉、再生・停止・コマ送り・シーク・音量操作を担当する。
- `MainWindow.PlaybackStatus.cs` は共通再生時刻、表示更新、性能とフレーム位置の表示を担当する。
- `MainWindow.StartupVerification.cs` は起動時の画面検証3件を担当する。
- `QualityGraphScale.cs` は画面グラフと画像出力で同じ縦軸範囲計算を使う。
- `QualityGraphPanel.cs` は約793行から354行になった。描画は `QualityGraphPanel.Drawing.cs`、軸と目盛りは `QualityGraphPanel.Axes.cs`、再生位置の入力は `QualityGraphPanel.Input.cs`、画面検証は `QualityGraphPanel.Verification.cs` に分けた。
- 凡例の配置・移動・折りたたみは `QualityGraphLegendController.cs`、左右グラフの最小化・復元は `QualityGraphPaneController.cs` が担当する。描画更新のためだけの委譲フィールドも除去した。
- 比較読み込みは成功・失敗の両方で世代番号を照合し、古い失敗が現在の状態表示を上書きしないようにした。参照されていなかった左右スロットの世代フィールドは削除した。
- 表示・記録の読み取り先がない通常プレビューの推定fps計算を削除した。実提示fpsの表示は従来どおり未測定として扱う。
- `App.xaml.cs` から専用テスト画面と検証用の起動分岐を `TestScreens/App.TestScreens.cs`、`TestScreens/App.Verification.cs` へ移した。主画面の検証専用partialクラス7件も `TestScreens/MainWindow/` に移した。起動引数の判定順は維持した。
- 専用テスト画面12種の `OnStartup`・`MainWindow` 設定・表示を1か所にまとめた。画面生成は選ばれた起動引数のものだけを `OnStartup` 後に行う。
- 検証ツール3件の旧アセンブリ名参照を修正し、グラフ操作の短時間検証を `Run-GraphPlaybackTest.ps1 -Auto -VerifyOperations` で実行できるようにした。総合検証ではビットレート確認に使う動画を `.mkv` と `.mp4` に絞った。
- 主画面・評価画面・CSV専用検証画面に重複していた、フレームCSVか集計CSVかを選んで保存する処理を `QualityCsvExporter.SaveAsync` に集約した。
- 主画面のFFprobeを使うコマ送り処理を `MainWindow.FrameStep.cs` に分けた。通常プレビューでは、復号失敗の通知をUIスレッドで実行する直前にも世代番号を照合し、切り替え前の失敗を破棄する。
- 左右の位置推定差が100 ms以上で1秒続いたときの再同期判定を `PlaybackDriftTracker` に分けた。動画切り替え・一時停止・停止・シークで計測をリセットし、前の状態のずれを次の動画へ持ち越さない。
- 部分評価の先頭復号と区間シークを照合する2つの経路から、画素ハッシュの不一致数と評価値の差の集計を `InputSeekComparison.Create` に集約した。欠落フレームは不一致として扱う。
- CFR・解像度・評価区間の共通条件を `EvaluationRangeValidator` に分けた。連続入力経路が範囲検証のためだけにSSIMを仮指定する処理を除いた。
- 通常評価・区間シーク検証・連続入力評価で重複していたFFmpeg/FFprobeの起動設定とプロセス終了要求を `EvaluationProcess` にまとめた。各経路の進捗解析とエラー文言は維持した。
- 連続入力の2経路に重複していた区間番号・元動画時刻への進捗換算を `PartialEvaluationProgress.FromCompletedFrames` に集約し、指標ごとのFFmpegフィルター指定も1か所にまとめた。
- 先頭復号と区間シークのフレーム選択式を `EvaluationFrameSelector` に集約した。開始PTSとCFR換算の条件は維持した。
- 同じ動画が同時に登録されないよう、FFprobe実行中のパスを予約する。成功・ファイル不存在・FFprobe失敗のどの場合も予約を解除する。一覧選択イベントの一時抑止と元状態の復元も共通化した。

主画面の分割ではメソッドと状態の動作を変えていない。`partial` の共有状態は残っており、ファイル間の依存はまだ強い。

## 検証

- 各コード変更後のReleaseビルドは警告0・エラー0。
- 各コード変更後の `tests/Run-Tests.ps1 -NoRestore` は合格。進捗の区間境界テストを1件追加し、現在は64件。
- 起動時検証3件、主画面の一覧・選択、シーク、比較操作、グラフ、グラフ画像保存のアプリ内自動検証が合格。
- グラフ分割の各段階では、凡例・最小化・目盛り・ファイル選択・進捗位置を含む評価画面検証と、主画面グラフ・画像保存の対象検証を実行した。
- プレビュー選択の整理後に、一覧の選択維持、3モードの左右切り替え、一時停止・再生状態維持、比較再生を実動画で確認した。古い比較読み込み失敗の表示抑止は、画面検証から失敗通知を模擬して確認した。実際のFFmpeg失敗を同時発生させた試験ではない。
- 推定fps計算の削除後は、通常プレビューの反映フレーム時刻・グラフ・再生制御の一致と一時停止を実動画で確認した。実提示fpsと負荷の再測定は行っていない。
- 起動分岐と検証専用partialクラスの移動後、Releaseビルド、MSTest 59件、総合検証ツールの品質実計算・主画面・比較操作6条件が合格。画面起動の共通化後もMSTest 59件と専用画面5種の自動検証が合格。グラフ操作の短時間検証も合格。グラフ再生の35秒×8条件の計測は今回完走させていない。
- CSV共通化後はReleaseビルドとMSTest 59件、CSV専用画面、主画面評価、評価結果画面の自動検証が合格。コマ送り分離後はビルドと59件、主画面のシーク・比較検証が合格。プレビュー失敗通知の修正後はビルドと59件、通常プレビュー検証が合格。古い失敗通知を実際の復号失敗で競合させた試験は行っていない。

- 同期判定の整理後に `tools/Run-FeatureChecks.ps1 -NoBuild` を実行し、当時のMSTest 61件、品質評価の実計算、主画面の一覧・評価・シーク・グラフ・比較、比較操作6条件が合格した。
- 部分評価の照合共通化後はReleaseビルド、MSTest 63件が合格。`Run-InputSeekTests.ps1 -Quick -SkipBuild` と `Run-ContinuousInputTests.ps1 -Quick -SkipBuild` で生成動画の画素ハッシュ・評価値を確認した。その後、両ツールを `-SkipBuild` で再実行し、実動画を含む全条件の画素・評価値・中止・進捗の確認も合格した。

## 次の対象

1. 主画面では動画の読み込み中に削除・選択変更を行う場合の非同期結果を確認する。左右再生の共通時刻と右音声消音も引き続き確認する。
2. 部分評価は入力シーク・画素形式ごとの条件が残る。追加の共通化は実動画で検証できる単位に限定する。
3. 変更が集中する設定画面は、次の機能追加時に必要な範囲を整理する。

分割だけでは総コード量は大きく減らない。今後は変更対象のファイルを狭め、重複した計算や状態管理を確認できた範囲で共通化する。
