# 動画品質アナライザー C#・WPF版

Windows 11 / .NET 10 / WPFで開発中の動画品質アナライザーです。完成版の方針は[新仕様書](docs/CSharp_WPF_仕様書.md)、資料の一覧は[文書案内](docs/README.md)を参照してください。

C#への移行は決定済みで、現在のプレビュー試作は性能合格として扱います。当面、追加の高速化や旧版との性能比較は行いません。以下は現在の試作の操作方法と、過去の検証内容です。

試作の実装範囲と合否基準は[移行検証仕様書](docs/移行検証/CSharp_WPF_移行検証_仕様書.md)、操作を含む試験は[テスト仕様書](docs/移行検証/CSharp_WPF_移行検証_テスト仕様書.md)を参照してください。

## 起動

手軽に試す場合は、作業フォルダーの`アプリを起動.cmd`をダブルクリックしてください。画面が開いたら「追加」から`test-data`内の動画を2本選び、「再生」を押します。動画ファイルを起動ファイルへドラッグ＆ドロップして登録することもできます。

作業フォルダーでPowerShellを開き、配置済みの.NET 10 SDKを使います。

```powershell
.\tools\dotnet\dotnet.exe restore .\VideoQualityAnalyzer.Wpf.sln --configfile .\NuGet.Config
.\tools\dotnet\dotnet.exe build .\VideoQualityAnalyzer.Wpf.sln -c Release --no-restore
.\tools\dotnet\dotnet.exe .\src\VideoQualityAnalyzer.App\bin\Release\net10.0-windows\VideoQualityAnalyzer.StageA.dll
```

`tools/ffmpeg-9.0.2-essentials_build/bin/ffprobe.exe`と`ffmpeg.exe`を自動検出します。FFmpegは全動画の共通プレビュー表示に必要です。

動画ファイルのフルパスを起動コマンドの後に並べると、起動時に登録できます。空白を含むパスは引用符で囲んでください。

## 操作

1. 「追加」またはドラッグ＆ドロップで動画を登録します。最初の動画が元動画です。一覧の動画を選んで「元動画に設定」から変更できます。
2. 一覧で比較動画を1本選ぶと元動画と並べて表示します。2本以上選んだ場合は一覧順の先頭2本を表示します。選択を外すと、元動画と直前または先頭の比較動画を表示します。
3. 再生、一時停止、停止、秒単位の移動、シークバー、1コマ送り、左側の音量・ミュートを操作できます。右側は常に消音です。
4. 1コマ送りは必要時にFFprobeで左動画のフレームPTSを取得します。取得できない場合は平均fpsで近似したことを表示します。
5. 動画の下には左右の「再生位置からの換算fps」を表示します。再生時刻付近には左右の現在フレーム位置と全フレーム数を表示します。現在位置は平均fpsと再生時刻からの推定です。全数はファイル内のメタデータがあればその値を使い、なければ長さと平均fpsから推定します。

すべての動画の映像は同じFFmpegのRGB変換を通し、WPFの画像として表示します。手元の可逆圧縮ファイルとAV1を左右に置き、初回フレームと再生位置の進行を画面で確認しました。RGBフレームをCPU側へ取り出す暫定方式のため、約30 fpsの実提示達成は未確認です。rawvideo出力にはPTSがないため、プレビューの提示時刻は平均fpsから推定します。左音声は従来のMediaElementが開ける非AV1動画のみ対応し、AV1の音声は未実装です。

## 完成版への組み込み状況

通常アプリで左右の動画を選び、「ワイプ・差分比較」を押すと、現在位置を元フレーム番号へ換算して比較画面を開きます。通常プレビューは一時停止します。比較画面では登録済みの動画を選択でき、検証済みのFFmpeg連続復号でワイプとヒートマップを表示します。通常利用ではぼかし選択を表示しません。

現段階の比較画面は別ウィンドウで、音声は出ません。通常の2画面と比較表示を同じ画面内で切り替える統合、音声、品質評価などは引き続き実装対象です。

組み込み後の比較操作は `tools/Run-ComparisonOperations.ps1 -MainApp` で自動確認できます。

## 測定結果の読み方

- 画面のCPU使用率とメモリはアプリの実測値です。GPU利用率と実際のハードウェアデコード使用状況はまだ不明と表示します。
- 「再生位置からの換算fps」は各動画の再生位置が約1秒で進んだ量に平均fpsを掛けた参考値です。フレーム欠落や重複は検出しません。画面へ実際に提示された異なるソースフレームを正確に数えていないため、左右の実提示fps、提示PTS差、初回フレーム提示時刻、シーク完了時刻は「未測定」です。`MediaOpened`までの時間は準備時間として別に記録します。
- 診断ログは通常、`%LOCALAPPDATA%\VideoQualityAnalyzer.StageA\logs`にJSON Lines形式で保存します。動画のフルパスは記録せず、匿名のIDを使います。
- [測定結果](docs/移行検証/benchmark-results.md)に実施状況と制約を記載しています。当時の測定上の制約は記録として残します。今後の方針は新仕様書に従います。

## GPU単一動画実験

段階Bの最初の描画実験は`experiments/VideoQualityAnalyzer.GpuPreview`にあります。手元の1440×1080動画の先頭300フレームをD3D11子ウィンドウへ渡します。

手元のAV1とH.265で2画面のGPU実験を操作する場合は、`GPU実験を起動.cmd`をダブルクリックしてください。右動画の候補2本を読み込み、切り替え、±5秒・先頭シーク、一時停止・再生、1コマ送り、停止を試せます。一時停止・停止中のシークは、左右の新しいフレームを表示したまま再生を再開しません。表示領域が他のウィンドウに隠れないようにしてください。PowerShellから`& '.\GPU実験を起動.cmd' -Stats`と実行すると、Flip方式のDXGI提示統計も画面に表示します。

```powershell
$video = (Get-Item -LiteralPath 'test-data\攻殻機動隊_ av1 --qvbr 32 --vpp-yadif.mkv').FullName
.\tools\dotnet\dotnet.exe .\experiments\VideoQualityAnalyzer.GpuPreview\bin\Release\net10.0-windows\VideoQualityAnalyzer.GpuPreview.dll $video
```

通常起動はRGBフレームをCPU側へ取り出してからGPUへ渡す方式です。AV1の先頭300フレームが画面に出ることを再確認しました。画面の枚数は`Present`へ渡した数で、実提示fpsではありません。

`--direct`を指定すると、Media FoundationからDXGIサーフェスを受け取り、GPU内の別テクスチャへコピーしてからD3D11 VideoProcessorで変換します。CPUへフレームを取り出さずにAV1とH.265の先頭300フレームを画面表示できました。デコーダーのサーフェスをVideoProcessorへ直接渡すと`Present`で停止したため、GPU内コピーを挟んでいます。可逆圧縮の巨大ファイルはNV12出力設定で失敗しました。ハードウェアデコードの実使用と約30 fpsの実提示評価は未完了です。

2本の動画パスと`--direct`を渡すと、左右それぞれのReaderを別作業で進め、共通時計以下の最新PTSを選んで描画します。開始PTSは各動画の先頭フレームを基準に揃えます。AV1＋H.265、AV1＋AV1、H.265＋H.265の先頭300フレームを画面確認しました。同時再生の900フレーム読み取り上限は解除し、動画の終端または操作による中断まで読み取ります。

```powershell
$left = (Get-Item -LiteralPath 'test-data\攻殻機動隊_ av1 --qvbr 48 --vpp-yadif.mkv').FullName
$right = (Get-Item -LiteralPath 'test-data\攻殻機動隊_icq50.mp4').FullName
.\tools\dotnet\dotnet.exe .\experiments\VideoQualityAnalyzer.GpuPreview\bin\Release\net10.0-windows\VideoQualityAnalyzer.GpuPreview.dll --direct $left $right
```

右動画の候補を追加する場合は、そのパスをコマンド末尾へ並べます。画面上部で右動画を切り替え、`-5秒`、`+5秒`、`先頭へ`で左右を同時にシークできます。切り替え中は左のReaderを維持し、右のGPU入力を作り直します。

画面の枚数は描画要求数、PTS差は最後に描画要求した左右のソースPTS差です。切り替え後の時間も初回の**描画要求**までであり、ディスプレイへの実提示時刻、実提示fps、同期精度ではありません。左音声はこのGPU実験に未接続で、可逆圧縮ファイルもMedia FoundationのNV12出力設定に失敗します。通常アプリのFFmpeg共通表示は引き続き利用できます。

`-Stats`はDXGIが報告する提示IDを各ソースPTSへ対応付け、直近約3秒の提示ID増分を観測時間で割った参考fpsを表示します。「対応なし」は提示IDをソースPTSに結び付けられなかった数、「同一PTS」は連続した提示IDに同じPTSが付いた数です。さらに、開始後の相対ソースPTS 2秒以上32秒未満について、左右の提示ID、異なるPTS、1秒ごとの枚数、描画候補から破棄されたPTSを`measurement-results/gpu-*.json`に1回保存します。ファイル名のみを記録し、動画のフルパスや音声データは保存しません。再生・シーク後は新しい実験としてアプリを起動し直してください。

現在の`-Stats`同時再生は比較実験のため`Present`の同期間隔を0にしています。ウィンドウの遮蔽や複数画面環境での統計の妥当性と各フレームの厳密な画面提示時刻は未確認です。30秒集計はソースPTS区間の参考値であり、約30 fpsの規定測定や外部計測との照合はまだ行っていません。実測結果と未実施項目は[測定結果](docs/移行検証/benchmark-results.md)に記載しています。

## 静止フレームの左右比較

PowerShellから`& '.\GPU実験を起動.cmd' -Compare`で比較画面を開けます。最初は可逆圧縮参照動画とH.265動画の元フレーム150を表示します。画面上で左右の動画を選び直すと、現在表示中の元フレーム番号で左右の画像、差分ヒートマップ、平均RGB差を自動更新します。差分の強調倍率は4・16・64倍から選べます。「ヒートマップのぼかし」は、ぼかしなし・弱・中・強を選べます。左右を同じ範囲でぼかしてから差を計算し、左右の元画像は変えません。弱・中・強はそれぞれ3×3・5×5・9×9画素の範囲です。ぼかし中の平均RGB差はぼかし後の値として表示します。GPU同時再生画面でも、一時停止または停止して左右のCFR換算フレーム番号が一致した状態で「静止フレーム比較」を押すと、その番号から開けます。

境界を動かす比較を試す場合は`& '.\GPU実験を起動.cmd' -Wipe`で開けます。比較画面の「表示」からも「境界比較（ワイプ）」へ切り替えられます。映像上の黄色い境界線を左右にドラッグすると、その左側に左動画、右側に右動画の**同じ元フレーム番号**を重ねて表示します。0%は右だけ、100%は左だけになります。端でも境界線をつかんで戻せます。境界操作では再復号やヒートマップ再計算を行いません。

比較画面の「再生」を押すと、選択した2本をFFmpegで連続復号し、同じ元フレーム番号の組でヒートマップとワイプを更新します。再生中に動画を選び直した場合は表示中の元フレーム番号から新しい組で再生を続け、一時停止中なら新しい静止画像を表示したままにします。表示モード・境界・差分強調・ヒートマップのぼかしも再生中に変更でき、「一時停止」「停止」も使えます。現在の再生比較は**同解像度・同フレームレートのCFR素材**向けで、音声は出ません。画面内のfpsはWPFへの描画要求であり、実画面表示の判定には外部キャプチャを別に使います。

「指定番号へ移動して再生」は、入力した元フレーム番号から左右をそろえて再生し直します。当時の性能の合格条件は、冒頭2秒を除く連続30秒に含まれる元フレームの欠落率**3%以下**です。手元の`30000/1001` fps素材では900枚中27枚までを許容します。`tools/Run-ComparisonBenchmarks.ps1 -Repeats 3`で全6組のワイプとヒートマップを反復測定し、`tools/Run-ComparisonOperations.ps1`で一時停止・再開・シーク後の左右一致を確認できます。外部のデスクトップ画像照合には`tools/Run-ComparisonCapture.ps1`を使います。結果は[測定結果](docs/移行検証/benchmark-results.md)に記録します。

同じフレームレートのCFR素材では、指定番号に近い位置へFFmpegでシークしてから復号します。比較画面が最初の静止フレームを表示した後、そのまま「再生」を押すと、保持していた左右の復号器で次のフレームから続けます。動画や番号を変更した場合は新しく開き直します。近傍シークが従来の先頭からの復号と同じ画素になるかは`tools/Verify-ComparisonSeek.ps1`で、動画選択による自動更新は`tools/Run-ComparisonSelectionTests.ps1`で確認できます。

静止比較はFFmpegで各動画の**同じフレーム番号**を独立して復号し、共通のBGRA形式で比較します。可逆圧縮参照動画も対象にできます。現在の5本は同一解像度・約29.97fpsの同じ元映像で、参照動画のコンテナ開始PTSは0.467秒です。比較にはその開始PTSの差ではなく、元フレーム番号を使います。色範囲や圧縮方式の影響も差分に含まれるため、平均RGB差だけで品質の優劣を決めません。再生中の比較は連続復号した対応フレームから計算します。VFR素材、異なる解像度の比較は未対応です。

一時停止・コマ送り・停止中シークのPTS照合を再実行するには、GPU実験アプリへ`--direct --verify-frames`と左右の動画パスを渡します。一時停止保持、10コマ送り、シークなど15操作を自動実行し、3本目の動画パスがあれば右切り替えも加えて16操作にします。左右のCFR換算フレーム番号、描画要求PTS、取得できた場合はDXGI提示IDに対応したPTSを`measurement-results/frame-operations-*.json`へ保存して終了します。画面が隠れた実行ではDXGI提示を確認できない場合があり、各操作の`PresentationConfirmed`で区別します。失敗時は`frame-operations-failed-*.json`に操作名とエラーを保存し、終了コード1を返します。保存する動画情報はファイル名のみです。この照合は同一ソースフレーム時刻の確認であり、画素の一致や画面の目視確認を代替しません。
