# 配布時のデバッグ情報

Release構成では、ルートの `Directory.Build.props` で開発フォルダーのパスを `/_/` に置き換える。アプリと参照DLLの双方へ適用する。Debug構成は対象外。

PDBはportable形式で生成して開発側に保管する。PDBに実パスを含むSourceLink情報を残さないようReleaseではSourceLinkを無効にする。DLLと対応するPDBはリリースごとに組で保管する。

`CopyOutputSymbolsToPublishDirectory=false` に加え、`Directory.Build.targets` で収集後の発行ファイルから `.pdb` を除外し、参照DLLに付随するPDBも配布しない。過去の発行先に手動で追加したファイルなどは残る可能性があるため、配布前は空の発行先と再検査を推奨する。

この設定はソースコードに直接書かれたパスや外部ファイルの内容、Microsoft提供のapphost内のMicrosoft側ビルドパスを変更するものではない。

## 確認結果（2026-11-11）

- `tools/dotnet/dotnet.exe build src/VideoQualityAnalyzer.App/VideoQualityAnalyzer.App.csproj -c Release -p:PublishProfile=ReleaseProfile -t:Rebuild -m:1 /nodeReuse:false`：警告0、エラー0。
- `tools/dotnet/dotnet.exe publish src/VideoQualityAnalyzer.App/VideoQualityAnalyzer.App.csproj -c Release -p:PublishProfile=ReleaseProfile -m:1 /nodeReuse:false`：成功。
- build138の発行物はexe1本・DLL4本・JSON2本、PDBなし。UTF-8・UTF-16の文字列検査で開発フォルダー名・ユーザー名・PC名を検出せず。DLLのPDB参照先は `/_/` 配下になった。
- アプリ・Core・Media・Diagnosticsの再生成PDB4本も同じ文字列検査に合格。
- `tests/Run-Tests.ps1 -NoRestore`：34件合格。
- Visual Studio画面からの発行操作は未確認。全種類の個人情報・秘密情報が存在しないことを保証する検査ではない。
