# 公開バージョンとビルド番号

公開バージョンは `src/VideoQualityAnalyzer.App/VideoQualityAnalyzer.App.csproj` の `Version` を手動で変更する。形式は `1.0.0` のような3つの数値。

2026-11-20：ショートカット操作とアプリアイコンの更新を反映し、公開バージョンを **1.3.1** に更新した。第4桁のビルド番号は従来どおりGitのコミット数から自動採番する。

1.3.1への更新時、Releaseビルドは警告0・エラー0、`tests/Run-Tests.ps1 -NoRestore` は64件合格。exeのファイルバージョン先頭3桁とアセンブリバージョンが1.3.1であることを確認した。公開用のビルド番号はコミット後の再ビルドで確定する。

2026-11-16：部分評価の連続入力方式と評価区間のみのプレビュー再生を追加したため、公開バージョンを **1.1.0** に更新した。第4桁のビルド番号は引き続きGitのコミット数から自動採番する。

更新時の確認：`tools/dotnet/dotnet.exe build src/VideoQualityAnalyzer.App -c Release --no-restore -m:1 /nodeReuse:false` は警告0・エラー0、`tests/Run-Tests.ps1 -NoRestore` は57件合格。バージョン更新後の次の作業予定は未定。

通常のビルド・発行では、アプリのファイルバージョンを `公開バージョン.GitのHEADまでのコミット数` に自動設定する。例：公開バージョン1.0.0、コミット数132なら `1.0.0.132`。Windowsのexeのプロパティの「詳細」で確認できる。製品バージョンには.NET SDKによるコミットIDも付く。

- GitコマンドをVisual Studioから実行できる環境と、全履歴を持つGit作業コピーが必要。GitHubのソースZIPだけではビルドできない。
- GitHub Actionsで使う場合も全履歴を取得する（checkoutの `fetch-depth: 0`）。浅いクローンは番号の誤認を防ぐためエラーにする。
- 未コミットの編集や同じコミットの再ビルドでは番号は増えない。コミット数はブランチ間で同じになる場合があるため、元コードの識別には製品バージョンのコミットIDも使う。
- コミット数の上限は65534。上限に達する場合は採番方式を変更する。
- 公開用はコミット後に発行する。コミット自体でも数が増える。
- `ReleaseProfile` の発行先は `bin/Release/net10.0-windows/publish/アプリ名-v公開バージョン-buildコミット数-ランタイム/`。例：`VideoQualityAnalyzer-v1.0.0-build134-win-x64`。発行処理でコミット数を取得してから名前を確定する。同じコミット・バージョンの再発行は同じ場所を使用する。

## 確認結果（2026-11-11）

### Visual Studioの発行先修正

追加修正：利用者の再発行ログでは、プロファイル判別を追加した後も既定の出力先だった。プロファイル名の引き継ぎを必要とする条件を撤廃し、アプリのすべての発行で `PrepareForPublish` の直前に命名する。通常ビルドでは発行先の処理は行わない。ログに「配布ファイルの出力先」を表示する。CLIで `-r win-x64 -p:BuildingInsideVisualStudio=true -p:PublishDir=bin/Release/net10.0-windows/win-x64/publish/` を指定し、プロファイル指定なしでも命名済みの出力先になることを確認。MSTest34件合格。Visual Studio画面そのものからの操作は未確認。

利用者のログでは発行成功だが、出力が `bin/Release/net10.0-windows/win-x64/publish/` になっていた。命名処理をプロファイルからプロジェクトへ移し、`PublishDir` と `PublishUrl` をローカルで更新できるプロパティとした。プロファイルを `WebPublishProfileFile` で渡す場合もReleaseProfileを判別する。

`tools/dotnet/dotnet.exe publish` に `-c Release`、`-p:WebPublishProfileFile=プロファイルの絶対パス`、`-p:ProjectToOverrideProjectExtensionsPath=アプリcsprojの絶対パス`、`-p:PublishDir=bin/Release/net10.0-windows/win-x64/publish/`、`-m:1 /nodeReuse:false` を指定し、命名済みフォルダー `VideoQualityAnalyzer-v1.0.0-build136-win-x64` への発行成功を確認。参照プロジェクトへのプロファイル適用を防ぐ指定も含めた。テスト依存情報を復元後、`tests/Run-Tests.ps1 -NoRestore` は34件合格。Visual Studio画面からの再発行は未確認。
